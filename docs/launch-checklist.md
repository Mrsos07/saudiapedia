# قائمة التحقق قبل الإطلاق | Launch checklist

كل بند غير مؤشّر إلى أن يُرفق دليل تحقق فعلي وتاريخ ومسؤول. وجود الكود أو اختبار hook وهمي لا يعني نجاح تكامل قاعدة البيانات أو اعتماد المحتوى. لا نشر إنتاجي ولا اتصال PostgreSQL/S3 تم تنفيذهما ضمن مهمة الاختبارات وأداة الاستيراد.

## 1. النطاق والمحتوى: مانع إطلاق

- [ ] اعتماد مخزون الإطلاق والموارد التحريرية. الموجود 30 موضوعًا ثنائي اللغة / 60 مقدمة غير معتمدة؛ هدف 150 موضوعًا / 300 صفحة اقتراح تخطيطي غير منجز. لا تُعرض أعداد التخطيط بوصفها مقالات منشورة.
- [ ] تحويل المقدمات إلى مواد موسوعية موسعة أصلية، لا فقرات حشو؛ استكمال التاريخ والمدن والأعلام والتراث بحسب المخزون المعتمد. وجود 13 منطقة و7 ملوك و3 دول لا يعني تغطية شاملة.
- [ ] تعيين مؤلف/باحث ومحرر عربي ومترجم ومراجع حقائق وناشر مسؤول؛ توسيع سياسة التأليف والمراجعة وإظهار الاعتمادات الحقيقية عند توفرها. لا أسماء أو تواريخ مراجعة مختلقة.
- [ ] تدقيق يدوي لكل ادعاء وتاريخ واسم وحدود جغرافية، وتوثيق الصفحة/الإصدار أو URL مستقر والمصدر الداعم لكل ادعاء. مصادر 25 مدخلًا أوليًا ما زالت فارغة؛ مراجع UNESCO الخمسة لا تغطي بقية المحتوى ولا تعني اعتمادًا بشريًا.
- [ ] مراجعة 1727 مقابل تحالف 1744، وبداية الدولة الثالثة 1902 مقابل إعلان المملكة 1932، والتمييز بين الأئمة وملوك المملكة، وفترة الحكم والعمر؛ عدم تخمين التحويل الهجري/الميلادي.
- [ ] تدقيق الشخصيات والأدوار والتواريخ المفتوحة والمناصب الحالية، وتمييز الوقائع عن التفسير والخلاف التاريخي. أي إحصاء جديد يحمل سنة ومصدرًا ولا يُختلق لإكمال التصميم.
- [ ] مطابقة النسختين في المعنى والأسماء والعناوين والحقائق وترتيب الأقسام والمراجع، مع دليل مصطلحات وتهجئة وتحويل صوتي معتمد.
- [ ] مراجعة المصدر يدويًا وحقوق الاقتباس وإعادة الصياغة وروابط المراجع؛ رفض المصادر الوهمية أو اعتبار مجرد استجابة HTTP دليلاً على صحة المحتوى.
- [ ] إقرار سياسة التصحيح، قناة اتصال عاملة، مسؤول الاستجابة، وجدول إعادة مراجعة المحتوى والتصريحات الزمنية؛ مراجعة سياسة الخصوصية والشروط والاستقلال عن الجهات الحكومية.

## 2. تشغيل محلي وفحوص آلية

- [ ] إنهاء تكامل الواجهة و`package.json` للسكربتات الموثقة في README؛ تسجيل إصدارات Node/Next/Payload المستخدمة.
- [ ] نجاح `npm run lint` و`npm run typecheck` و`npm run test` و`npm run build` و`npm run test:e2e` مع حفظ النتائج، ثم اختبار `npm run start`.
- [ ] تشغيل `node --import tsx --test tests/unit/*.test.ts`: عدّ البيانات واللغات والروابط، التطبيع والبحث، وصول مجهول/أدوار، hooks الاعتماد والتراجع، Users، MIME والبايتات الأصلية للصور. لا تتطلب الاختبارات قاعدة بيانات ولا تُجري استيراد seed.
- [ ] بدون بيانات CMS: `/ar` و`/en` يعرضان المعاينات بوضوح؛ `/admin` صفحة إعداد؛ REST يعيد 503 دون تهيئة قاعدة البيانات أو كشف أسرار.
- [ ] إعداد CMS غير صالح ينتج خطأ واضحًا بلا الرجوع إلى المعاينة أو طباعة بيانات اتصال؛ قاعدة مهيأة بلا مقالات مؤهلة تعرض حالة فارغة لا seed.

## 3. PostgreSQL وREST وLocal API: اختبارات تكامل مرحلية

استخدم قاعدة مرحلية منفصلة مع الحسابات الحقيقية الأربعة وطلبات مجهولة؛ لا تستخدم `overrideAccess:true` لاختبار الجمهور. الاختبارات الوهمية تتحقق من الدوال، لا من استدعاء Payload لها في كل مسار.

- [ ] المجهول لا ينشئ مستخدمًا بـ POST عادي، ولا يقرأ مسودات/إصدارات/مكتبة مصادر/علاقات مراجعين/وسائط خاصة. تحقق من REST وLocal API الذي يغذي الصفحات والبحث.
- [ ] تهيئة أول مسؤول خلف حاجز خاص عبر `/admin`؛ اختبار محاولتين متزامنتين لـ first-register ينجح منهما حساب واحد فقط، ورفض التسجيل الأول بعد وجود مستخدم. لا تمسح Users لإعادة التهيئة.
- [ ] editor/translator ينشئان ويعدلان المسودات ولا يعتمدان أو ينشران أو يغيران الأدوار. reviewer ينشر ويراجع ولا يدير المستخدمين؛ administrator يديرها. منع الحذف العادي للمستخدمين ومنع تزوير الدور/الـ bootstrapKey/حقول الاعتماد.
- [ ] اختبار حساب المراجعة والتوقيت المسجلين فعليًا في قاعدة البيانات؛ منع نشر مادة ناقصة أو مصادر غير HTTP(S) أو عناوين URL ببيانات اعتماد.
- [ ] تعديل محتوى معتمد بالقيم القديمة approved/published من محرر يسحب الاعتماد والنشر؛ المراجع دون موافقة صريحة جديدة لا يحتفظ باعتماد موروث. حذف/إعادة ترتيب/تعديل مصفوفات الحقائق والمراجع والصور مشمول.
- [ ] حفظ `draft=true` يلغي النشر في الجدول الرئيسي، وليس الإصدار الجديد فقط؛ استعادة الإصدارات للمراجع/المسؤول فقط وتخضع لنفس hooks، واستعادة draft-only مرفوضة.
- [ ] بعد إلغاء نشر أي ترجمة، تختفي الثنائية من الصفحة والبحث والخريطة وsitemap والنتائج الجديدة دون نسخة عامة مخزنة؛ تحقق من proxies وCDN أيضًا. لا يمكن سحب نسخة سبق تنزيلها.
- [ ] القيود الفريدة `(slug, locale, section)` و`(translationKey, locale)` وbootstrap singleton تمنع التكرار بما فيه تحديثات المسودة والتزامن؛ لا تكتفِ بقراءة إعداد الفهارس.
- [ ] الثنائية تتطلب وثيقتين منشورتين ومعتمدتين؛ حذف/خصوصية/عدم اكتمال إحدى اللغتين يمنع fallback مختلطًا. اختبر اختلاف المفتاح والفقرات والحقائق والمصادر وperiod/kind، وتطابق ترتيب URL، وأكثر من 100 وثيقة لاختبار pagination.
- [ ] مراجعة عدم استخدام cache عابر للطلبات للبيانات العامة الحساسة للإلغاء؛ توثيق أن القراءة المجزأة ليست snapshot ذريًا وأن الطلب الجاري قد سبق تغيير الحالة.
- [ ] تثبيت `PAYLOAD_SECRET` قوي خارج المستودع، origin HTTPS واحد لـ CORS/CSRF، cookies آمنة، قفل خمس محاولات وتوقيت الجلسة، وحماية proxy من إساءة تسجيل الدخول/API. لا يوجد وعد باستعادة بريدية قبل إعداد مزود بريد واختباره.

## 4. أداة seed: تشغيل اختياري على staging

- [ ] تهيئة مسؤول حقيقي أولًا، ثم تشغيل الاستيراد يدويًا بعد مراجعة الهدف دون طباعة بيانات الاتصال. لا تنشئ الأداة مستخدمًا ولا تطلب كلمة مرور عبر المحادثة.
- [ ] تأكيد إنشاء 60 وثيقة draft كحد أقصى من اللغتين، مع مفاتيح `seed:${section}:${slug}` وحقائق وفقرات محلية وصور غير مرتبطة، وصفر نشر/رفع/موافقة.
- [ ] إعادة التشغيل لا تغير أي وثيقة موجودة أو تاريخ تحرير؛ التعارض بالـ slug أو مفتاح الترجمة يؤدي للتجاوز، لا الاستبدال. تعديل مسودة ثم إعادة التشغيل يحافظ على التعديل.
- [ ] تجربة فشل جزئي ثم الاستئناف؛ لا ضمان لمعاملة واحدة لكل الاستيراد أو تشغيل متزامن. قد تتطلب الأزواج المتعارضة تسوية يدوية؛ لا يُعاد ربط وثائق المحررين تلقائيًا.
- [ ] رفض إنتاج بلا `ALLOW_SEED_IMPORT=true`؛ وجود المتغير لا يغني عن backup/review ولا يجعل المحتوى صالحًا للنشر. تحقق من `process.exitCode` وإغلاق Payload دون كشف أسرار.

## 5. الصور وS3 والحقوق

- [ ] S3 خاص دائم إلزامي لـ CMS الإنتاجي؛ ضبط القيم الأربع وendpoint عند الحاجة، حظر الوصول العام وACLs العامة، صلاحيات أقل امتيازًا للمخزن المحدد، وعدم تفعيل signed redirects أو تعطيل Payload access control.
- [ ] ملف خاص لا يُقرأ عبر REST أو `/api/media/file/...` أو URL تخزين مباشر؛ reviewer يجيز الوسائط منفصلة عن المقال، وتعديل/استبدال محرر يسحب إتاحتها العامة فورًا.
- [ ] اختبار JPEG/PNG/WebP/AVIF حقيقي، رفض SVG/GIF وSVG متنكر كـ JPEG والملفات التالفة، حد 10 MiB وحد البكسلات؛ تحقق من WebP الناتج وأبعاده وإزالة metadata. فحص malware خدمة إضافية غير متوفرة تلقائيًا.
- [ ] استجابات الملفات `private, no-store` و`nosniff`؛ لا CDN cache أو Next image optimization يحتفظ بوسائط قابلة لسحب الوصول. اختبر عدم تسرب الروابط الخاصة من علاقات الصور واستعمال fallback الصحيح.
- [ ] ربط الاعتمادات العامة بكل صورة: المؤلف والمصدر والترخيص والتعديلات من [سجل الأصول](asset-licenses.md)، والالتزام بـ CC BY-SA عند التعديل. توثيق Natural Earth للشعار دون ادعاء شعار رسمي.
- [ ] تصحيح كل alt/caption بعد رؤية الصورة؛ لا تعتبر منظر الرياض صورة ملك ولا تستخدم صورة الحِجر لتوثيق الدرعية. سجل الأصول أحدث من تعليقات image slots القديمة؛ الترخيص لا يثبت ملاءمة الصورة للموضوع.
- [ ] إبقاء Flaticon مؤجلًا حتى توثيق أصول محددة وترخيصها واعتماداتها؛ عدم إضافة مكتبة أيقونات بديلة أو الادعاء بترخيص غير مفحوص.

## 6. تجربة المستخدم والخصوصية والفهرسة والأداء

- [ ] `/ar` RTL و`/en` LTR، والتنقل بين اللغتين يحافظ على الموضوع؛ المسارات المفقودة تعيد 404 محلية دون سقوط إلى لغة أخرى. لا تعكس الاتجاه الجغرافي للشعار عند RTL.
- [ ] فحص التنقل بلوحة المفاتيح وقارئ الشاشة والفوكس والتباين وإعادة التدفق على الهاتف والطباعة ونسخ الاستشهاد، مع WCAG 2.2 AA هدفًا للتحقق لا شهادة تلقائية.
- [ ] الخريطة مخطط عام وروابط نصية إلى 13 منطقة فقط؛ المضلعات الإدارية الدقيقة تظل عملًا لاحقًا بمصدر جغرافي مرخص ومراجعة مختص، ولا تعرض حدود اليوم بوصفها حدود دولة تاريخية.
- [ ] اختبار البحث العربي بعلامات التشكيل والتطويل والألف والأرقام وEnglish casing؛ النتائج حسب لغة العرض ومن مدخلات عامة مسموحة فقط. `pg_trgm` والبحث التقريبي والفهرسة الموسعة غير منجزة.
- [ ] تحميل Zain مرة واحدة وتطبيقه على النص والنماذج باللغتين؛ اختبار fallback عند حجب Google Fonts وقياس CLS، وتوثيق طلبات Google الخارجية والخصوصية قبل تفعيل الخدمة العامة.
- [ ] `SITE_INDEXABLE=false` افتراضيًا؛ تحقق من noindex الفعلي على المعاينات والبحث ومن sitemap خالٍ من المسودات، ثم canonical وhreflang المتبادل وstructured data دون تواريخ/اعتمادات وهمية. لا تفعّل الفهرسة إلا بعد موافقة المحتوى والأمان.
- [ ] قياس صفحات الهاتف الرئيسية والمقالات والصور: Lighthouse هدف مختبري ≥90 لا نتيجة مدعاة؛ بعد الإطلاق قياس p75 LCP ≤2.5s وINP ≤200ms وCLS ≤0.1. تحسين الصور مع الحفاظ على شروط الترخيص وسلامة الوسائط الخاصة.

## 7. الترحيلات والنسخ الاحتياطي والتشغيل

- [ ] توليد migration أولية على قاعدة نظيفة و`CMS_DB_PUSH=false` وإعداد S3 مماثل للإنتاج؛ مراجعة SQL والفهارس وجداول الإصدارات وحقل media prefix وcommit الناتج. لا توجد migration إنتاجية مُثبتة بهذه المهمة.
- [ ] إبقاء schema push معطلًا في الإنتاج؛ تطبيق migrations بمهمة واحدة وصلاحيات مخصصة، والتحقق من الهدف دون طباعة الاتصال. عدم توليد baseline من قاعدة سبق دفع schema إليها.
- [ ] نسخة احتياطية مشفرة من PostgreSQL **والوسائط الخاصة**، وسياسة احتفاظ ومسؤول، وتمرين استعادة واقعي على بيئة منفصلة مع قياس زمن الاستعادة وفقد البيانات المقبول.
- [ ] تجربة ترقية ثم rollback، واختبار استعادة الروابط بين الوسائط والمقالات واللغتين. انتقال الملفات المحلية إلى S3 ليس آليًا؛ يلزم نسخ وتحقق منفصلان.
- [ ] تهيئة الاستضافة وDNS وTLS والأسرار الدائمة والمراقبة والإنذارات لتسجيل الدخول وأخطاء DB/S3 والترحيلات والأداء؛ تعيين مالك تشغيل ونافذة صيانة وخطة حوادث.
- [ ] الموافقة النهائية بعد جميع الأدلة، ثم نشر فعلي منفصل وتحقق دخاني على البيئة المنشورة. لا تضع علامة إنجاز بناءً على README أو build وحده.
