# موسوعة المملكة | Kingdom Encyclopedia

موقع مستقل بالعربية والإنجليزية مبني بـ Next.js وTypeScript وPayload وPostgreSQL، وليس جهة حكومية. المساران العامان `/ar` و`/en`، والإدارة `/admin`.

## الحالة الفعلية

- بيانات المعاينة الأولية: **30 موضوعًا ثنائي اللغة** (60 مقدمة) غير معتمدة، تُستخدم فقط عند عدم تهيئة CMS. وهي منفصلة عن قاعدة المحتوى الحالية.
- تحقق 2026-09-23 من قاعدة Supabase الحالية أظهر **78 وثيقة مقالات معتمدة ومنشورة** و**38 صورة**. نُسخت الصور إلى مخزن Supabase الخاص `saudiapedia-media`، وتحقق تطابق بايتاتها وإتاحتها عبر CMS ومنع القراءة المجهولة من التخزين المباشر، دون تعديل المقالات أو الحسابات.
- **150 موضوعًا / 300 صفحة هدف تخطيطي مقترح، وليس محتوى منجزًا**. يلزم التوسع التحريري والتحقق من الوقائع والمراجع والترجمة قبل الإطلاق.
- الخريطة الحالية مخطط حدود عام وروابط للمناطق، وليست مضلعات تفاعلية لحدود المناطق. البحث الأولي تطبيع نصي داخل الذاكرة؛ `pg_trgm` والفهرسة المتقدمة عمل لاحق.
- ملفات التشغيل على Render جاهزة؛ لم تُنشأ خدمة Render أو يُختبر النشر على استضافته بعد. تبقى مراجعة المصادقة وMFA وحدود الطلبات والنسخ الاحتياطي والاتصال الداخلي لدى مزود قاعدة البيانات متطلبات تشغيل مستقلة.

## النشر على Render

1. أنشئ **Blueprint** من هذا المستودع وفرع `main`، وحدد **Blueprint Path: `.devin/render.yaml`**، واترك Root Directory جذر المستودع. القالب يستخدم خدمة Node وخطة مدفوعة `1c-2g` في Singapore؛ راجع الخطة وتكلفتها قبل الموافقة. لم تُنشأ خدمة أو تُجرَ عملية دفع آليًا.
2. بديل الإنشاء اليدوي: اختر **Web Service / Node** واضبط Node على `22.23.2`، وBuild Command على `npm ci --include=dev && npm run render:build`، وStart Command على `npm run render:start`، وHealth Check على `/api/health`.
3. أضف الأسرار من لوحة Render فقط: `DATABASE_URL` لحساب `kingdom_runtime` الحالي، و`PAYLOAD_SECRET` الحالي المستقر، و`S3_ACCESS_KEY_ID` و`S3_SECRET_ACCESS_KEY`. لا تستخدم حساب `postgres` أو المهاجر، ولا تنقل أسرارًا عبر المحادثة أو Git.
4. أضف شهادة Supabase الرسمية كـ **Secret File** باسم `supabase-ca.crt`. يستخدم التشغيل المسار `/etc/secrets/supabase-ca.crt` مع التحقق من الشهادة واسم الخادم؛ لا تضع خيارات SSL في رابط قاعدة البيانات كي لا تتجاوز الإعداد الصريح.
5. إعدادات التخزين غير السرية موجودة في القالب: bucket `saudiapedia-media`، والمنطقة `ap-northeast-1`، وS3 endpoint للمشروع، و`S3_FORCE_PATH_STYLE=true`. المخزن خاص ومفاتيح Supabase S3 مخصصة للخادم وتتجاوز RLS على مستوى المشروع، فلا تُستخدم في المتصفح.
6. القالب يولّد `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` مرة واحدة. في الإنشاء اليدوي، وفّر قيمة base64 عشوائية بطول 32 بايت واحتفظ بها ثابتة بين النشر والتشغيل. اضبط `CMS_REQUIRED=true` و`CMS_DB_PUSH=false` و`CMS_ALLOW_BOOTSTRAP=false` و`SITE_INDEXABLE=false` و`SKIP_INSTALL_DEPS=true`.
7. دون نطاق مخصص تُستخدم قيمة `RENDER_EXTERNAL_URL` الفعلية لتوحيد عنوان الموقع وCMS. للنطاق المخصص اضبط `NEXT_PUBLIC_SITE_URL` و`CMS_SERVER_URL` على أصل HTTPS نفسه، ثم **أعد البناء والنشر**؛ تغيير العنوان دون إعادة البناء يُرفض.
8. لا يُشغّل القالب seed أو migrations أو إنشاء مستخدم أول تلقائيًا. استخدم قاعدة Supabase الحالية بحساباتها ومحتواها. فحص الصحة يتحقق من الإعدادات وقاعدة البيانات ووجود مسؤول والجداول الأساسية؛ لا يُعد بديلًا لاختبار الصور والدخول على عنوان Render النهائي.

تفاصيل الصلاحيات والقيود والتخزين في [دليل CMS](docs/cms.md). حدّث النسخ الاحتياطية لقاعدة البيانات والوسائط واختبر الاستعادة قبل الإطلاق؛ Supabase S3 لا يدعم versioning لاستعادة الكائنات المحذوفة. أبقِ الفهرسة مغلقة حتى اعتماد الإطلاق.

## تشغيل محلي

1. استخدم إصدار Node.js المدعوم من الحزم المثبتة (يفضل Node.js 22 LTS)، وثبّت الاعتماديات بـ `npm install` من جذر المشروع.
2. شغّل `npm run dev` وافتح `http://localhost:3000`. لا تحتاج المعاينة العامة إلى قاعدة بيانات.
3. إعداد CMS اختياري: أنشئ `.env.local` بالإعدادات الموضحة في دليل CMS، واملأ القيم محليًا فقط؛ لا تنسخ ملفات قد تحتوي أسرارًا تشغيلية. غياب `DATABASE_URL` و`PAYLOAD_SECRET` معًا يسمح بالمعاينة المحلية فقط إذا لم يكن `CMS_REQUIRED=true`؛ الإعداد الجزئي خطأ ولا يسمح بالرجوع إلى المعاينة.
4. لإدارة حقيقية جهّز PostgreSQL موجودًا، وسرًا عشوائيًا بطول 32 محرفًا على الأقل، و`CMS_SERVER_URL` للأصل الصحيح. اتبع [دليل CMS](docs/cms.md)؛ لا ترسل الأسرار في المحادثات أو تضعها في Git.
5. احمِ `/admin` و`/api/users/first-register` قبل تهيئة الحساب الأول، ثم فعّل `CMS_ALLOW_BOOTSTRAP=true` مؤقتًا لعملية التهيئة الخاصة وأزله بعدها. كلمات المرور الجديدة تتطلب 15–128 محرفًا؛ استعادة كلمة المرور بالبريد معطلة حتى تجهيزها واختبارها. بعد تسجيل المسؤول، أنشئ أدوار التحرير والترجمة والمراجعة من Users؛ لا تنشئ الأداة حسابات افتراضية.

**تفعيل CMS يستبدل بيانات العرض الأولية** بأزواج عربية/إنجليزية مكتملة ومتوافقة، معتمدة ومنشورة فقط. `null` يعني غير مهيأ؛ المصفوفة الفارغة تعني CMS مهيأ بلا أزواج مؤهلة. أخطاء الاتصال ليست سببًا للرجوع إلى المعاينة. يشترط التطابق في `translationKey` والقسم والرابط وترتيب الحقائق والفقرات والمصادر والقيم المشتركة. حفظ المسودة يلغي نشرها فورًا؛ التعديل يتطلب إعادة الاعتماد وفق قواعد المراجعة.

## الأوامر والتحقق

الأوامر التالية موجودة في `package.json`. بناء Render يمسح أسرار CMS والتخزين من بيئة عملية البناء، ولا يتصل بقاعدة المحتوى؛ يتطلب التشغيل الإعدادات الحقيقية.

| الأمر | الغرض |
| --- | --- |
| `npm run dev` | خادم التطوير |
| `npm run build` / `npm run start` | البناء ثم تشغيل نسخة الإنتاج محليًا |
| `npm run lint` / `npm run typecheck` | فحص الأسلوب والأنواع |
| `npm run test` | اختبارات الوحدات دون قاعدة بيانات |
| `npm run test:e2e` | اختبارات المتصفح بعد البناء، على المنفذ 3100 ودون CMS حقيقي |
| `npm run render:validate` | فحص القالب مقابل مخطط Render الرسمي؛ يتطلب اتصالًا بالإنترنت ولا ينشئ خدمة |
| `npm run render:build` | بناء بعناوين الإنتاج دون الاتصال بقاعدة البيانات أو S3 |
| `npm run render:check` | فحص متغيرات البيئة دون اتصال خارجي أو إثبات صلاحية المفاتيح |
| `npm run render:start` | التحقق من الشهادة وعنوان البناء ثم الاستماع على `0.0.0.0:$PORT` |
| `npm run cms:seed` | استيراد المسودات عبر `scripts/seed.ts` |
| `npm run cms:generate-types` | توليد أنواع Payload ومراجعة الناتج |
| `npm run cms:migrate:create` / `npm run cms:migrate` | إنشاء ترحيل ومراجعته ثم تطبيق الترحيلات على قاعدة محددة |

المشغل المباشر للوحدات هو `node --import tsx --test tests/unit/*.test.ts`. تستعمل الاختبارات استيرادات نسبية وطلبات Payload وهمية محددة الأنواع؛ تختبر المحتوى والبحث والأدوار والاعتماد والمستخدمين والصور دون قاعدة بيانات. لا تثبت سلامة REST الفعلية أو قيود PostgreSQL أو S3. تُشغّل هذه الفحوص قبل رفع التحديثات؛ لا تُعد دليلًا على نجاح نشر Render نفسه. راجع [قائمة الإطلاق](docs/launch-checklist.md).

## استيراد مسودات CMS

شغّل `npm run cms:seed` بعد ربطه بـ `node --import tsx scripts/seed.ts`، وبعد تهيئة المسؤول عبر `/admin`. تحمل الأداة `.env.local` بواسطة `@next/env` قبل استيراد إعداد Payload؛ متغيرات البيئة الموجودة لها الأولوية.

- تستورد اللغتين لكل موضوع، حتى 60 وثيقة جديدة، بمفتاح مشترك `seed:${section}:${slug}`، وكلها `_status=draft` و`reviewStatus=draft`.
- تستخدم مسؤولًا موجودًا فعليًا من قاعدة البيانات، لا هوية مختلقة. استعلام الهوية منخفض المستوى مخصص للأداة المحلية الموثوقة؛ عمليات المقالات تستخدم Local API مع `overrideAccess:false` و`user` المسؤول وتشغّل hooks.
- لا تحدّث ولا تحذف وثائق موجودة، حتى المنشورة أو المحررة. تتجاوز تطابق مفتاح الترجمة/اللغة أو القسم/الرابط/اللغة. أعد تشغيلها بعد فشل جزئي لإضافة المفقود فقط؛ لا تشغّل نسختين متزامنتين. التعارض يحتاج مراجعة بشرية وليس دمجًا تلقائيًا.
- تستورد الحقائق والفقرات والمراجع باللغة المناسبة. لا تنشئ صورًا أو مستخدمين أو موافقات؛ علاقة الصورة غير محددة ويستخدم العرض الصورة البديلة. راجع ملاءمتها ووصفها وحقوقها قبل النشر.
- في `NODE_ENV=production` ترفض العمل إلا مع `ALLOW_SEED_IMPORT=true`. هذه موافقة على إدخال **مسودات تجريبية** وليست تصريح نشر؛ يفضل الاستيراد في بيئة تطوير/مرحلية. لا تطبع الأداة بيانات الدخول أو أخطاء الاتصال الخام، وتغلق Payload في `finally`.

## الحقوق والخصوصية والإطلاق

- خط **Zain إلزامي** للعربية والإنجليزية. تحميل Google Fonts الخارجي يرسل طلبات إلى Google قد تتضمن IP وبيانات المتصفح؛ وضّح ذلك في سياسة الخصوصية واختبر الخط البديل عند الحجب. لا تضف تحميل خط مكررًا.
- توثيق الصور والشعار ومصادرها وتراخيصها في [سجل الأصول](docs/asset-licenses.md): صور Wikimedia Commons بتراخيص CC BY/CC BY-SA، وشعار مبني على مخطط Natural Earth العام. يلزم إظهار الاعتمادات المطلوبة علنًا؛ الشعار ليس شعار الدولة الرسمي ولا خريطة حدود قانونية. راجع تعليقات الصور القديمة في بيانات المعاينة مقابل هذا السجل قبل النشر.
- Flaticon مؤجل حتى التحقق من تراخيص أصول محددة وأسماء مؤلفيها؛ لا أيقونات غير مرخصة ولا مكتبة أيقونات بديلة.
- أبقِ `SITE_INDEXABLE=false` افتراضيًا للمحتوى غير المراجع وبيئات الاختبار. تحقق من تنفيذه فعليًا في robots/metadata/sitemap أثناء تكامل الواجهة، ولا تفعّل الفهرسة قبل اعتماد الإطلاق؛ `noindex` ليس حماية وصول.
- CMS الإنتاجي يتطلب PostgreSQL وHTTPS وS3 خاصًا دائمًا؛ التخزين المحلي للتطوير فقط. الترحيلات والنسخ الاحتياطي لقاعدة البيانات والوسائط واختبار الاستعادة متطلبات إطلاق، وليست خدمات تم تنفيذها.
- راجع [حالة المحتوى](docs/editorial-status.md)، و[تشغيل CMS](docs/cms.md)، و[قائمة الإطلاق](docs/launch-checklist.md). توسيع سياسة التأليف ونسب المواد للمؤلفين والمراجعين الحقيقيين، ومراجع على مستوى الادعاء، وآلية التصحيح وجدول إعادة المراجعة أعمال مطلوبة؛ لا تختلق أسماء أو تواريخ اعتماد.
